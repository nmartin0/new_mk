| G73 | **APSL 2.0 is weak, file-level copyleft — not permissive.** From the `APPLE_LICENSE` in current XNU: *"(c) If You Externally Deploy Your Modifications, You must make Source Code of all Your Externally Deployed Modifications either available to those to whom You have Externally Deployed Your Modifications, or publicly available… for as long as you Externally Deploy the Covered Code or twelve months"*. "Externally Deploy" (§1.4) covers sublicensing and distribution **and** use to provide a service to third parties. Reciprocity attaches to the covered files, not to what links them — which is how Apple ships XNU inside a proprietary OS. APSL **1.x**, which `xnu-123.5` carries, also triggered on *internal* deployment; 2.0 (6 Aug 2003) narrowed it. Consequence for this project: taking any XNU file means carrying a permanent source-publication duty that the OSF Free Copyright does not impose. |
| G74 | **The modern i386 bring-up sequence, from NetBSD 10.** `init386()` (`i386/machdep.c`, 2,015 lines) runs: `lwp0` setup → **`cpu_probe()`** → **`cpu_init_msrs()`** → **`cpu_speculation_init()`** → PAE selection → GDT/IDT/TSS → `pmap_bootstrap` → `consinit` → symbols. `locore.S` (1,899) handles the boot protocol first; `mainbus` does discovery after. **Discovery is ACPI-first with MP-table fallback**, and all four systems use the same pattern — `x86/mainbus.c`: `acpi_present = acpi_probe(); if (acpi_present) mpacpi_active = mpacpi_scan_apics(...); if (!mpacpi_active) mpbios_scan(...)`. |
| G75 | **Same job, four sizes.** ACPI/MADT: NetBSD `mpacpi.c` 1,160, FreeBSD `acpica/madt.c` 778, OpenBSD `acpimadt.c` 476 (+`acpi.c` 3,555), **Haiku `boot/.../acpi.cpp` 251**. MP-table fallback: 1,492 / 1,296 / 1,122 / (inside Haiku's `smp.cpp` 638, which does both). LAPIC: 1,022 / 2,462 / 488 / **394**. IOAPIC: 622 / 1,269 / 860 / (in `arch_int.cpp` 510). AP startup: NetBSD `cpu.c` 1,600 + `mptramp.S` 242, FreeBSD `mp_x86.c` 1,786, OpenBSD `cpu.c` 936 + `mptramp.s` 231, **Haiku `arch_smp.cpp` 237**. CPU identification: 1,265 / 2,742 / (in machdep) / 1,845. **Haiku is the model for this project** — a from-scratch kernel with no legacy doing the whole job in ~1,500 lines, and doing ACPI discovery **in the boot path**, handing the kernel a digested structure (`acpi_validate_rsdp`, `acpi_check_rsdt` with XSDT-then-RSDT, `acpi_find_table(signature)`, scanning EBDA + `0xE0000–0x100000`, then walking `ACPI_MADT_LOCAL_APIC` / `ACPI_MADT_IO_APIC`). That placement keeps the parser out of early-kernel constraints — no allocator, no pmap, no locks — which is where a 1995 kernel is least accommodating. |
| G76 | **What 7.3 lacks in x86 platform code, by tier.** *Tier 1, genuinely required (~1,500–2,000 lines):* ACPI table access, MADT walk feeding `mp_v1_1.c`'s existing tables with `find_fps()` as fallback, LAPIC/IOAPIC lifted out of `mp_v1_1.c` (including x2APIC MSRs, which 7.3 has nothing for), HPET or LAPIC-timer timekeeping with TSC calibration, Multiboot2 with framebuffer and memory-map tags. *Tier 2, before untrusted code runs:* a real CPUID layer, SMEP/SMAP/NX (K15), hotpatching (K29), speculation mitigations (K30). *Tier 3, skip:* microcode loading, AMD errata tables (`errata.c` 674), frequency scaling (`est.c` 1,436, `powernow.c`), thermal (`coretemp.c`, `odcm.c`), MTRR (`mtrr_i686.c` 771), hypervisor paravirt (`hyperv.c` 1,158, `vmt.c`), IPMI — over 6,000 lines in NetBSD alone, near-zero value for a QEMU-hosted system. Also absent from 7.3 and worth knowing: `x86_tlb.c` 546 (TLB shootdown as its own subsystem), `intr.c` 2,386 (interrupt routing/priority/sharing/MSI), `cpu_rng.c` 341, `cpu_topology.c` 216, `bios32.c` 310 + `bioscall.S` 93 (a controlled route to BIOS services — the disciplined answer to the INT 41h problem). |
| G77 | **Mach's portability claim, measured.** *Assembly share of the core MD path* (pmap, locore, trap, context switch, FPU, descriptors, AP startup, LAPIC): **OSFMK 7.3 33.1%** (5,371 of 16,207 lines), NetBSD 15.3%, OpenBSD 16.6%, **FreeBSD 3.3%** (453-line `locore.S`). *Whole MD tree:* 7.3 8.6% (7,737 asm / 81,983 C), NetBSD 8.7%, FreeBSD 6.0%, OpenBSD 11.3% — a dead heat, so the issue is **concentration in the boot and switch core**, not volume. *Architecture leakage into MI code* (`i386`/`x86`/`amd64` identifiers in the machine-independent core): **7.3: 5 files, 15 occurrences** across 117,579 lines of `kern`+`ipc`+`vm`; NetBSD 4/6; OpenBSD 5/8; **FreeBSD 33/80**. **Conclusion: the original portability claim holds — 7.3's MI core is as clean as NetBSD's and five times cleaner than FreeBSD's, which is why it carries working ppc, hp_pa and Sequent ports off one core. The dated part is the assembly concentration (K27), and that is a direct K13 cost.** Caveat: 7.3's `i386/` includes device drivers that the BSDs keep in `sys/dev`, so its MD layer is smaller relative to the others than the raw totals suggest — making the assembly concentration slightly worse than the table shows. |

| G81 | **Permissive low-level C worth reaching for, measured.** **Limine** — BSD-2-Clause, C + assembly, **IA-32 (i686+) and x86-64**, BIOS *and* UEFI, speaks Multiboot 1, Multiboot 2, Linux and its own protocol, reads ISO-9660 and FAT; its own protocol supplies memory map, framebuffer, modules, **ACPI tables guaranteed mapped** (base revision 4: RSDP, RSDT, XSDT and everything they point at) and **SMP initialisation — it starts the APs**. Conforming to Multiboot2 (K11) buys a UEFI-capable loader with no code to port. **uACPI** — **MIT**, 19 C files / 23,702 lines, table-only subset ≈ 3,600 (`tables.c` 1,647, `utilities.c` 1,156, `stdlib.c` 723, `shareable.c` 71); ships its own overridable stdlib, needs only "memcpy, strcmp, … + snprintf" plus a kernel API (map/unmap, alloc/free, mutexes, ticks); **avoids recursion deliberately** because kernel stacks are tiny, where ACPICA's `Load`/`LoadTable` grow the stack per call; CI-tested in 32-bit and 64-bit modes. **Better fit than ACPICA for K8a/K8b** — MIT rather than dual BSD/GPL, smaller, and hardened for exactly this constraint. **flanterm** — BSD-2, 6 files / 4,423 lines, framebuffer terminal in C, pairs with K11's framebuffer. Note Haiku and Mach-US are **C++**, so design reference only under the C-only rule. |
| G82 | **Bootloader and installer, assessed.** OpenBSD's i386 bootloader is small and clean — `stand/boot` 780 lines, `biosboot` 1,163, `cdboot` 565, `stand/libsa` 6,957 (23 C + 4 asm: `biosprobe`, `memprobe`, `diskprobe`, `pciprobe`, `smpprobe`, `gateA20`, `elf32`/`elf64`, `bioscons`, `pxe`), plus shared `sys/lib/libsa` 15,605 — BSD/ISC with exactly **one** advertising-clause file (`pxe.c`). Both are Phase 11 concerns — consequences of U5, not ways to reach it. |

| G84 | **FreeBSD's VM evolution, release by release** (`vm_map.c` / `vm_page.c` / `vm_pageout.c` / `swap_pager.c`): 2.0.5 — 2,670 / 1,175 / 960 / 1,709; 3.0 — 2,944 / 1,753 / 1,332 / 1,691; 4.0 — 3,064 / 1,930 / 1,433 / 1,960; 6.0 — 3,344 / 1,742 / 1,649 / 2,527. | G85 | **UVM's announcement is a defect list for 7.3's VM.** Cranor's NetBSD announcement: the old Mach code "uses 'shadow and copy object chains' which lead to the pesky 'swap memory leak' problem which can only be fixed with complex vm_object collapse code which has proved troublesome"; UVM did "elimination of the Mach vm_object cache — object persistence is now fully under the control of the object being mapped"; and added "page loanout… without the need for data copies". These are known hazards in the code this project runs, analysed at length in Cranor's dissertation — worth reading before L23, since `MAP_SHARED` coherence runs straight through the object chains. |

| G95 | **The distributed inheritance, measured — and it is already configured for i386.** `dipc/` 27 files / **27,722 lines** (distributed IPC — ports that work across nodes), `xmm/` 32 files / **19,798** (the memory-object layer and `NORMA_VM`'s distributed shared memory), `flipc/` 6 files / 2,704, `uk_xkern/` 4 files, plus the transport in `i386/kkt/` (`kkt.c`, `if_kkt.c` — KKT over a network interface). **Nineteen NORMA configurations exist in `conf/AT386/`**: `DEBUG+NORMA` and `+APIC`/`+MP`/`+flipc`/`+net`/`+net+flipc`/`+net+flipc+kgdb`, the `FAST+NORMA` and `PRODUCTION+NORMA` variants, and `STD+COMPAQ+2+NORMA` / `STD+COROLLARY+6+NORMA(+debug)`. `conf/config.norma` enables `DIPC`, `DIPC_STATS`, `DIPC_TIMER`, `NORMA_TASK`, `NORMA_VM`, `FAST_IDLE`, `!ADVISORY_PAGEOUT`; the AT386 overlay adds `NORMA_SCSI` and `DYNAMIC_NUM_NODES`. **Capability on paper:** transparent port migration across nodes, remote task creation, distributed shared memory with remote paging, shared SCSI, dynamic node count, Ethernet transport. **Caveats:** never built in this revival (builds are `FAST`/`DEBUG` without NORMA); 1997 code; `xmm` sits directly under the pager that L23 rebuilds; and `config.norma` enables `FAST_IDLE` while `config.mp` calls it "broken MP". **No other surviving Mach has any of this** — XNU deleted it in 1999, GNU Mach never had it, Utah's line never carried it. |
| G96 | **Tru64's distributed filesystem is unavailable, and what was released is the wrong thing.** TruCluster's cluster filesystem (CFS) was never open-sourced: HP announced in December 2004 that it was abandoning the migration of AdvFS, TruCluster and LSM to HP-UX and laid off most remaining Tru64 developers. What HP did release, on 23 June 2008, was **AdvFS** — the *local* filesystem — under **GPL-2.0-only**, chosen deliberately for Linux-kernel compatibility.
