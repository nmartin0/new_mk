# DECISIONS

Why the work is shaped the way it is. Three kinds of record, each of
which exists because reconstructing it later proved expensive:

- **Decisions (D)** — settled choices, with the evidence that settled
  them. A decision here is not revisited without new evidence, and when
  one *is* reversed the reversal is recorded in place rather than
  replacing it.
- **Pitfalls (P)** — known traps, each with the check that found it.
  Several constrain decisions listed below, which is why they come first.
- **Corrections (H)** — claims that were made and turned out to be
  wrong. Kept, not deleted. A record that hides a wrong turn is worth
  less than one that shows it, because the next reader cannot tell which
  parts to trust (RULES.md 2.5, 7.11).

What is *open* is in `BACKLOG.md`; what was *measured* is in
`FINDINGS.md` and `FINDINGS2.md`; the *order* is in `ROADMAP.md`.

## 1. Pitfalls — known traps, with the check that found them

Each was verified against the tree or the host toolchain, not inferred. Placed before the decisions because several of them constrain decisions already made.

| ID | pitfall | check | mitigation |
|---|---|---|---|
| P1 | *(superseded — the problem is real, the conclusion was wrong)* **The bootstrap userland is runnable but unbuildable.** `binutils 2.42` reports **zero a.out targets**, so a modern toolchain cannot emit, link or patch i386 a.out. U1/U2 assumes `mach_init` — *our* program — is linked against NetBSD 1.0's a.out libc, which would require building and maintaining a period toolchain (binutils ~2.16, gcc 3.x). | `objdump --info`, `ld -V` on the build host | ~~Reorder Phase 3 to U3 → U2 → U1.~~ **The project solved it differently and better**: LITES's `SECOND_SERVER` `-i` flag points the server straight at `/sbin/init`, a working static NetBSD 1.0 a.out binary, so **nothing of ours needs linking against a.out libc at all**. `mach_init` is ported and committed as belt-and-braces, not as a dependency. The a.out measurement stands (binutils 2.42 has no a.out target; `nm` reports "file format not recognized" on `libc.a`'s members); the inference that it blocked progress did not. |
| P2 | **The kernel's clock is 32-bit and it is in the RPC interface.** `mach/time_value.h`: `time_value_t` is `integer_t seconds` (signed 32-bit); `mach/clock_types.h`: `tvalspec.tv_sec` is `unsigned int`. `time_value_t` appears in `mach_host.defs` on `host_set_time`, `host_adjust_time`, `host_get_time`. **L2's 64-bit `time_t` in LITES does not save the kernel boundary — it still wraps in 2038.** | read the headers and `.defs` | Widening is a **kernel ABI change** carried by MIG, so decide it **with L2**, not after (and see R33 for MIG's 64-bit gap). |
| P3 | **Dialect pinning does not cover generated code.** MIG emits ANSI prototypes (checked: `vm_user.c`), but LITES's `vnode_if.sh` emits **K&R** — `__INLINE__ int VOP_STRATEGY(bp)` with separate parameter declarations. R25 pins `-std=` for hand-written files only. | inspect generator output | Update the generators (`vnode_if.sh`, `makesyscalls.sh`) as part of R25, before GCC 15's `gnu23` default arrives. |
| P4 | **"Self-hosting" with a modern compiler means porting C++.** GCC has needed a C++11 compiler to build since 4.8; clang needs C++17. A C-only project cannot self-host either without a C++ runtime and libstdc++ on target. | compiler requirements | Decide deliberately: cross-compile indefinitely (fine, and what most projects do), or self-host with a C-only compiler for our own code while cross-building the toolchain. Do not let "self-hosting" mean "port libstdc++" by default. |
| P5 | **Two ABIs in one server.** Once `e_netbsd_sysent` (U4) runs beside `e_bsd`, one `proc` structure serves processes with different `time_t`, `off_t` and `sigset_t` widths. | design consequence of U4 + L2 | **Rule: the server's internal types are the modern ones; old personalities translate at the emulator boundary.** State it in `PRINCIPLES.md` (R12) or someone will widen a field "for the old personality" and corrupt the new one. |
| P6 | **QEMU is not hardware.** Everything is tested against one machine model; ACPI quirks, PCI interrupt routing, timer behaviour and firmware differences are exactly where real machines diverge — and exactly what Phase 6 touches. | scope of the current test setup | Keep a real-hardware target in view from Phase 6; prefer discovery paths with fallbacks (MADT with `find_fps()` behind it) over ones that assume QEMU's tidy tables. |
| P7 | **Scope, with precedent.** 181 items and one developer. The 2014 OpenMach revival never reached a boot (G41); OpenDarwin closed saying it "failed to achieve its goals in 4 years of operation" (G110); xMach stalled. | history | The defence is already in the plan and must not be deprioritised: **CI (R30)**, a bootable system at the end of every phase, and phases that each produce something testable. When something more interesting appears, R30 still comes first. |

## 2. Decisions made (D)

| ID | decision | date | rationale |
|---|---|---|---|
| D1 | Keep LITES as a separate server; design for optional collocation later | 17 Sep | Debuggability; 7.3 has kernel-loaded task support; MkLinux `bootstrap.conf` shows `-k`. |
| D2 | Buff up LITES with NetBSD code; do not port NetBSD wholesale | 17 Sep | LITES's Mach glue is the irreplaceable part; NetBSD's machine layer is the part not wanted. |
| D3 | NetBSD is the code donor; XNU is design-only | 17 Sep | Licence: BSD-2 vs APSL. GNU Mach GPL, reference only. |
| D4 | Target the current NetBSD ABI (10), floor 6.0 | 17 Sep | 64-bit `time_t`, `*at()`, ELF TLS all begin at 6.0. |
| D5 | Use NetBSD 5.0 as the *implementation model* for threading | 17 Sep | Smallest 1:1 libpthread (5,789 lines), no SA, no futex, no TLS requirement. LWP syscall numbers unchanged since. |
| D6 | Thread-keyed park/unpark before address-keyed futex | 17 Sep | Park maps onto Mach semaphores with no kernel change; futex must be in the kernel. |
| D7 | Take XNU's kernel-facing patterns, NetBSD's ABI | 17 Sep | Thread ports as identity, trampolines, exec-as-new-task, exceptions as inherited port. |
| D8 | The libc jump precedes threading | 17 Sep | `_lwp_create` takes a `ucontext`; NetBSD 1.0 has none. |
| D9 | Permissive donors are ACPICA and the BSDs; no Mach supplies this code | 17 Sep | GNU Mach GPL-2+, XNU APSL, Mach 4/xMach only 51 lines of stubs (G13, G14, G17). Avoid four-clause/advertising files (NetBSD `mpacpi.c`). Prefer BSD-2 sources as reading references so no obligation attaches. |
| D10 | One vocabulary per hardware concept | 17 Sep | Extend OSF's `apic.h`; do not import a competing register header (K9a). |

| D11 | RPCs carry values, in-line data or out-of-line memory — never a client pointer | 17 Sep | The server cannot dereference client memory; the emulator runs *inside* the process and can copy for free. This is the Mach-native replacement for `copyin`/`copyout`, and it shapes every interface in L2. |

| D12 | The emulator is the privileged half that lives inside the process | 17 Sep | Anything needing access to the client's own memory or registers belongs there, not in the server: copying data for RPCs (D11), building signal frames, TLS setup, thread creation, park/unpark, `getcontext`/`setcontext`. The server owns naming, policy and identity; the kernel owns mechanism. This is the rule that decides where each new call lands (L15, L9, U6). |

| D13 | Each BSD subsystem is rework, replace, or delete — decided before file-level work | 17 Sep | Rework: `kern`, `libkern`, `i386`, `ufs/ufs/ufs_lockf.c`. Replace from NetBSD: `netinet`, `net`, `ufs`, `nfs`, most of `miscfs`, `msdosfs`, `isofs`. Delete: `netiso`, `netccitt`, `netns` and the non-i386 architectures. Recorded properly in L38. |
| D14 | The glue changes before the BSD code | 17 Sep | The `lthread` split, caller identity, the readiness model and the ABI definitions all live in `server/serv` and `emulator`; most BSD-side work depends on them or is a replacement import. Doing the BSD side first means doing it twice (G52). |

| D15 | The endpoint is a Mach-aware libc; the emulator is the migration path, not the destination | 17 Sep | In the end state the emulator holds no UNIX policy — only the fd table, routing and signal frames, which is exactly what libc's lower half would hold. The trap bounce (program → kernel → back into the process → server) is pure overhead once libc can call servers directly. Keep the emulator while LITES is being dismembered, because it is what keeps the system bootable and testable throughout, and because a stock NetBSD userland is the bring-up strategy and the ABI test (Q10). Then link the same routing library into libc and drop the bounce; the emulator survives only for foreign binaries, or disappears. |

| D16 | The kernel provides mechanism only; protocol and policy live above it | 17 Sep | Tasks, threads, address spaces, ports, messages, memory objects, time, exceptions, notifications — plus X14's badge, X15's fast paths and X17's ledger charging. No files, no users, no processes, no POSIX. The routing library (X9) and any server-side helper (X11) are **userland**, shipped with libc or the servers, deletable without touching the kernel. The one unavoidable shared artefact is the wire format — the MIG `.defs` — which is an interface description, not code or policy. **Test for any proposed kernel addition: if it only makes sense because UNIX exists, it does not belong in the kernel.** |

| D17 | Stay on 7.3; do not rebase onto 6.1 | 17 Sep | G66 settles the licence question — OSF RI's own engineers name the microkernel's licence as the OSF Free Copyright, with the OSF/1 *server* as the encumbered component. 7.3's per-file grants are identical to 6.1's, and its advertising exposure in the i386 build is 17 files. Rebasing would cost the entire platform layer (APIC/MP, PCI, multiboot, ledgers, security tokens, NE2000, more SCSI) that 6.1 lacks. Import 6.1's userland instead (R28), and keep 6.1 and pmk1.1 as diff references. |

| D18 | "Mach first, BSD second" — with VM and ddb as the named exceptions | 17 Sep | For most subsystems the two do not compete: Mach has no `tree.h`, no `vsnprintf`, no timecounter, no GPT, no modern disassembler; BSD has no ports, no memory objects, no IPC. **ddb exception withdrawn (G119): the BSDs stripped the Mach-specific parts, so XNU is the reference there, not NetBSD.** For VM the exception stands — **FreeBSD's `sys/vm` *is* Mach's VM** — `vm_map.c`, `vm_object.c`, `vm_fault.c`, `vm_kern.c`, `vm_pageout.c`, `vm_init.c`, each carrying "Copyright (c) 1987, 1990 Carnegie-Mellon University … Authors: Avadis Tevanian, Jr., Michael Wayne Young" beside the Regents notice — and **the BSD `ddb`s are Mach's ddb**. For those two, the BSDs are the *first* place to look, not the second: same code, thirty years further on, under a licence that is a superset of ours. Note also (G121): FreeBSD's and XNU's VMs diverged from Mach and never converged — **no file from either can be swapped in**, so both are ports onto our own structures, FreeBSD first. Keep Mach's zone allocator and queue macros regardless — changing them touches everything and buys nothing. |

| D19 | **Source compatibility, not binary compatibility, is the goal** | 17 Sep | POSIX software may be compiled; it need not run unmodified. Consequences: (1) **skip NetBSD's 65 versioned syscall entries** — implement only the current forms, since they exist for NetBSD's own ABI history; (2) **choose 64-bit `time_t`/`off_t` and a clean `struct stat` from day one**, with no compat variants and no future transition; (3) **libc may call the routing library directly as C functions** — no syscall numbers, no trap, no dispatch table, which simplifies U4/X13 from "emit stubs that trap" to "emit wrappers that call"; (4) the emulator and its personality tables survive **only** as the bootstrap crutch for the 1.0 a.out userland, with a scheduled removal; (5) Q10 (do stock pkgsrc *binary* packages run) stops being the ABI test and becomes a nice-to-have — **replaced by "does pkgsrc build from source"**. What does *not* change: NetBSD's libc is still the source, because the libc choice is really the **userland** choice — NetBSD's `init`, shell and utilities expect NetBSD libc internals, and mixing a foreign libc (musl, picolibc, newlib) with a NetBSD userland trades a solved problem for an unsolved one. Its headers and ATF tests also remain the conformance specification, both of which are API-level and unaffected by ABI freedom. |

| D20 | The distributed subsystems are kept, revived and extended — not deleted | 17 Sep | Reverses the first draft of K12. `dipc`, `xmm`, `flipc`, `uk_xkern` and `i386/kkt` are ~50,000 lines giving **transparent cross-node IPC, remote task creation (`NORMA_TASK`), distributed shared memory and remote paging (`NORMA_VM`), shared SCSI (`NORMA_SCSI`) and a dynamic node count** — with nineteen i386 configurations already present (G95). No other surviving Mach has this: XNU deleted it in 1999, GNU Mach never had it, Utah's line never carried it. It also composes with section K rather than competing: a filesystem server reached through a port becomes a *distributed* filesystem when DIPC carries the port across nodes and XMM keeps its pages coherent — which is a better answer than porting a 1990s cluster filesystem (G96). Consequences: K12 prunes only dead architectures; a NORMA configuration joins CI (R4); `xmm` must be kept building through the pager rework rather than revived after it; and the distributed gaps — membership and quorum, failure detection, cross-node identity, time synchronisation — become work items rather than reasons to abandon the inheritance. |

| D21 | APSL adoption is permitted, quarantined, and last-resort | 17 Sep | The licence allows it (G97, §4 Larger Works) and the obligations are file-scoped, so adopting APSL code does not relicense the project. The cost is permanent and per-file: keep Apple's notice, mark every change with a date, publish modified source while deployed (or twelve months), and accept §5's patent caveat and §12's 30-day cure period. **Order of preference stands: (1) the original CMU/OSF content from 7.3 or 6.1, which is free and is the same code (G98); (2) permissive BSD or MIT sources; (3) APSL, quarantined under K39, only where Apple's own work is the thing wanted — principally the 32-bit evolution of these exact files (K40) and the x86_64 port (K41).** Read everything; import narrowly. |

| D22 | The build system is self-hosted POSIX make; the fork follows its own conventions | 17 Sep | **No CMake, and no build-system dependency that is not buildable from this tree.** The lineage stays pmake-derived — ODE now (R9/R20/R21), `bmake` only if R24 concludes it is worth the move — which is also consistent with pkgsrc (U10/U11) and with the early `bsd.port.mk` option (U12), both pmake dialects. References from other systems are **read-only design input**: PureDarwin's CMake (G111) is recorded as *their* answer to building Apple's sources, relevant only if K40/K41 ever moves from reading to compiling, and never as something this tree adopts. The same rule applies to conventions generally — Apple's, Linux's or anyone else's naming, layout, service model and process conventions are studied, not inherited. Where this fork needs a convention it does not have, it defines one and records it in `PRINCIPLES.md` (R12). |

| D23 | Source lives in `/usr/src` once self-hosting, with this system's own internal layout | 17 Sep | The convention is worth following where the userland already expects it — a NetBSD userland, its documentation habits and pkgsrc all assume `/usr/src`, and inventing a different root buys nothing. **But the layout inside it is this system's, not BSD's**: `osfmk/` (the kernel), `lites/` (the personality), `servers/`, `regress/`, `tools/`, `share/mk`, rather than pretending to BSD's `sys/` arrangement, which describes a monolithic kernel this system does not have. Consistent with D22: follow a convention where it costs nothing and is expected; define our own where the architecture differs. pkgsrc keeps its own root (`/usr/pkgsrc`) as it does everywhere. |

| D24 | Byte offsets stay canonical in the VM; the distributed protocol decides it | 17 Sep | `memory_object.defs` passes `vm_offset_t offset` in `data_request`, `data_supply`, `data_unlock`, `lock_request` and `data_error`, and XMM uses `vm_offset_t` 345 times — **byte offsets are what cross the node boundary** (G123). FreeBSD's `vm_pindex_t` is correct for a kernel where nothing leaves the machine and wrong for one where it does. Any adopted structure keyed on page index converts internally (`offset >> PAGE_SHIFT`) and never lets the index escape `vm_resident.c`. **The two conventions must not coexist.** |
| D25 | The external pager interface is inviolable — it is what makes the system distributable | 17 Sep | Our `vm_object` holds `struct ipc_port *pager`; XNU holds `memory_object_t pager`; **FreeBSD holds `objtype_t type` + `void *handle`, having deleted the interface when it went monolithic** (G122). A pager that is a port can be another task or another node; a pager that is a type tag is compiled-in code. **Therefore: no FreeBSD code touching the object↔pager relationship enters this tree** — `vnode_pager.c`, `swap_pager.c`, `vm_pager.c`, `vm_object_collapse`, and the per-page busy-lock model are on the do-not-import list (G125). What is safe from FreeBSD sits *below* the object and is protocol-agnostic: the radix trie, buddy allocation, superpage promotion. **XNU is architecturally safer than FreeBSD for VM work despite the licence**, because it kept the pager port, the shadow topology and the offset identity. |

| D26 | For IPC, adopt only what adds a field or changes a policy — never what replaces a structure | 17 Sep | Mirrors D25, for the other half of the kernel. DIPC puts **416 conditional hooks** through the five files at the heart of IPC — `ipc_kmsg.c` 116, `ipc_port.c` 77, `ipc_mqueue.c` 70, `ipc_right.c` 58, `mach_msg.c` 33, `ipc_object.c` 22 — and `struct ipc_port` carries `ip_dipc`, `ip_norma_xmm_object` and `ip_norma_xmm_object_refs` (G127). **So for VM, XNU was the safer donor (it kept the pager port); for IPC, XNU is the more dangerous one, because its improvements sit exactly where DIPC is instrumented.** **Take:** the port context word (X14), handoff on call (X15), XNU's kmsg type-and-threshold allocation scheme, `IE_BITS_EX_RECEIVE`-style use-after-free detection, immovable/pinned rights. **Take with distributed tests in place:** turnstiles — four port fields and one flag, with `ipc_kmsg.c` barely touched (G126). **Do not take:** the SMR entry-table name space (deleting `ipc_splay.c`/`ipc_table.c` breaks DIPC's proxy bookkeeping), `struct ipc_port` wholesale, vouchers, and the waitq-merged `ipc_mqueue` — which is also why `ipc_thread.c` must stay. |

| D27 | GPL is acceptable **for Linux device drivers and their emulation layer only** | 17 Sep | Reverses the blanket exclusion for this one category. Utah's Linux device-driver emulation (G163) — 323 files, 5,766 lines of glue (`linux_block.c` 2,590, `linux_net.c` 520, `linux_kmem.c` 481, `linux_irq.c`, `linux_dma.c`, `linux_autoirq.c`), drivers tracking Linux 1.3.68 — is usable, and so are Linux drivers themselves. **Scope is the whole of the exception: drivers and the shim that hosts them, nothing else.** No GPL code in the kernel core, the personality, the libraries or the tools. **Consequence to plan around: GPL code linked into the Mach kernel binary makes that binary GPL-derived on distribution.** The architecture already suggests the way out, and it is the direction K16 and X1 point anyway — **host the Linux drivers in a separate driver server talking to the kernel over Mach IPC**, so the GPL boundary falls on a process boundary and the kernel stays permissive. Record every such import in `IMPORTS.md` with its origin and licence, and keep it in its own subtree (K39's mechanics apply to GPL as much as to APSL). |
| D28 | LITES's GNU build layer stays unmodified until the ODE build is proven | 21 Sep | LITES ships two build systems: Utah's GNU layer (`configure`, the `Makefile.in` files, the `Makerules`, `conf/Makeconf.in`) and Helander's ODE Makefiles beside it. The tree builds LITES with the ODE ones (phase C); the GNU layer is what `tools/lites/build-lites.sh` still uses, and it is the reference the ODE build is checked against, object by object. Deleting vendor files is itself a deviation, so they stay, **untouched**, until the ODE build has been proven through C5 (servers enumerated, boot acceptance passed); then this is revisited, with evidence. **One exception, forced:** Utah's lowercase `makefile` is renamed `makefile.utah`, content unchanged, because BSD make reads `makefile` before `Makefile` and it shadowed the ODE build at LITES's top. Nothing used it. The GNU layer does not read the ODE Makefiles, and builds its own `conf/Makeconf` from `conf/Makeconf.in`, so ODE-side changes cannot affect it. **Revisit due (21 Sep):** the ODE build is proven through C5 — built from nothing by the documented steps, booted, every loadable section identical to the GNU route's — and `build-lites.sh` is retired, so nothing uses the GNU layer's `configure`, `Makefile.in` files or `Makerules`. Note that the ODE build still *reads* some of the GNU layer: `conf/MASTER`, `conf/files`, `conf/doconfig.sh`, `conf/gensym.awk`, `conf/newvers.sh`, `conf/copyright`, `conf/move-if-change`. **Decided (21 Sep): keep all of it, unmodified, as reference.** The unused files cost nothing, keep the vendor tree close to upstream, and are how the GNU build -- the reference every ODE-built object was checked against -- can be rebuilt at any time. Revisit only if they get in the way. |
| D29 | LITES builds into the object tree and installs to `/mach_servers/` | 21 Sep | **Build:** into `$MK_BUILD`'s object tree, where `bootstrap` and `default_pager` already are, so `boot-ide.sh` finds every server the same way. **Install:** `${MACH3_ROOT_SERVERS_IDIR}`, which OSF 7.3's `Buildconf` sets to `/mach_servers/`, with install names `startup` and `emulator`. Three precedents agree: OSF 7.3's own `bootstrap` and `default_pager` declare `IDIR = ${MACH3_ROOT_SERVERS_IDIR}`; UX 28's `install` rule copies its server to `${INSTALL_TREE}/mach_servers/startup` and its emulator to `/mach_servers/emulator`; LITES's `doc/install.freebsd` says to create `/mach_servers`. Built names follow LITES's own convention, `startup.${VERSION}.${CONFIG}`, as POE does with `poe.${VERSION}`. **Open conflict, deliberately left:** LITES's own ODE Makefiles install the emulator to `/special/` and `server/conf/template.mk` copies the server to `${EXPORTBASE}/special/` — POE's convention. Nothing here runs an install pass yet, so the vendor values stay until one does; that is when this is settled, and how ODE renames a file at install is verified rather than assumed. |
| D30 | Fragments below the threshold of copyright are credited, not licensed; anything larger follows the donor's licence | 21 Sep | The project borrows from Apple, NetBSD, CMU, Utah and others, and each borrowing must be compliant and traceable. **The test:** a fragment is below the threshold when it is a few lines at most -- the GNU maintainers' guide treats changes of *"less than 15 or so"* lines as not legally significant -- and has no creative expression of its own: a short phrase, which the Copyright Office does not register (37 C.F.R. § 202.1, de minimis authorship), or the natural or only way to express its idea (the merger doctrine). **Judge it per donor, across the project:** several small borrowings from one source can add up to a significant one, as the GNU guide warns. **When in doubt, it is above the threshold** -- reasonable minds differ about originality, and the conservative reading costs little. **Below the threshold:** a comment at the site naming the donor, the file and the release it came from, and saying that it is credited rather than licensed and why; the commit message records the reasoning. No licence text, which would wrongly assert that the donor's licence governs the file. **Above it:** the donor's licence governs. For permissive donors, their copyright notice and licence text travel with the code -- as SPDX snippet tags (REUSE) where it shares a file with differently-licensed code; for APSL, D21's quarantine and K39's mechanics; for GPL, only within D27's limits. **First application:** `j % 100` in `bbc_settime()`, from Apple's Rhapsody and XNU (G185). |
