# test_mk7.3 / LITES modernization — measured findings

Companion to the running list. Every entry here was measured from source or verified against a primary document, so it does not need re-deriving. Referred to by ID (G1, G2…) from the worklist's tasks, decisions and questions.

*Last updated: 17 September 2026 (rev 19).*

## The findings

| ID | fact |
|---|---|
| G1 | LITES `struct proc` has a single `p_thread`, per-process `p_siglist`/`p_sigmask`, `NSIG` 32, `sigset_t` = `unsigned long`. `proc_invocation.k_thread` exists but is **never assigned**. Syscall table: 211 entries; `sigaltstack` `UNIMPL`; no `poll`, `nanosleep`, `clock_gettime`, `sched_*`. |
| G2 | LITES signal delivery: server sends `signal_notify`; emulator's signal thread suspends, aborts, gets and sets the target's state; the handler is called from emulator C code; integer registers only; the async path (`SIGX4`) is compiled out because of a race. |
| G3 | OSFMK 7.3 ships `mach_services/lib/libpthreads` (~1,900 lines): threads via `thread_create`, blocking via Mach semaphores and lock sets, thread-self by stack arithmetic. Ancestor of Darwin's libpthread. |
| G4 | XNU (`xnu-12377`): per-thread `uthread` created with every Mach thread, mask inherited from the creating thread, `p_sigmask` deprecated; threads named by Mach thread port; `bsdthread_create` is pure Mach calls; `exec` swaps in a new task; exceptions→signals via a default exception port inherited from initproc; psynch and ulock are both address-keyed, hence kernel-only. Darwin has 32 signals, no `sigqueue`, no `timer_create`. |
| G5 | NetBSD release data: 1.0 a.out/139 syscalls/no `ucontext`; 2.0 LWP+SA/libpthread 7,834 lines; 5.0 1:1/libpthread 5,789/no futex/no ELF TLS/`time_t` 32-bit; 6.0 `time_t` 64-bit, `*at()`, rtld TLS; 10 329 syscalls, futex, 65 versioned entries. `_lwp_*` numbers (309, 320–322, 325) identical 5.0→10. i386 switched a.out→ELF in NetBSD 1.5 (Dec 2000). |
| G6 | 7.3 threading primitives that already exist: `thread_create`, `thread_create_running` (trap 84), `thread_terminate`, `thread_suspend`/`resume`, `thread_get_state`/`set_state`, `thread_abort`, **`thread_abort_safely`**, `thread_info`, `task_threads`, `thread_policy`, `thread_switch` (trap 61), `swtch`/`swtch_pri` (59/60), `clock_sleep_trap` (62), `thread_depress_abort`, per-thread and per-task exception ports (`thread_set_exception_ports`), semaphores with `semaphore_timedwait` and `semaphore_signal_thread`, lock sets with handoff, `mach_port_request_notification` (dead names). Semaphores are RPCs, not traps. |
| G7 | 7.3 has `i386_set_ldt(thread_act_t, …)` / `i386_get_ldt` in the `mach_i386` subsystem (`i386/user_ldt.c`, built `standard`), and `struct i386_thread_state` includes `gs` and `fs`. **Per-thread TLS is therefore available today with no kernel change.** |
| G8 | 7.3 SMP inventory: MP configs (`FAST+MP`, `DEBUG+MP`, `DEBUG+MP+RT`), `pseudo-device cpus 5`; `MP_V1_1` (Intel MP spec 1.1); `i386/AT386/mp/mp_v1_1.c` (1,225 lines) with `find_fps`, `lapic_init`, IOAPIC arrays, `cpu_interrupt`, `slave_boot`, `start_other_cpus`, `get_ncpus`, `slave_machine_init`; `slave_boot.S` (229); `mp_desc.c` (343, per-CPU descriptor tables); `i386_lock.S` (828, MP locks); per-CPU data through `%gs` with preemption counters (`cpu_data.h`); TLB shootdown in `intel/pmap.c` with `interrupt_processor()`; processor sets with run queues. `config.mp` disables `FAST_IDLE` with the comment "These are broken MP". |
| G10 | 7.3's shared-memory primitive is `default_pager_object_create` (an anonymous memory-object port) plus `vm_map` into any task at any offset. LITES already uses exactly this for its shared u-area: `init_main.c` creates one object sized `4*vm_page_size*(maxproc+1)`, and `mapin_user()` maps each process's slice read-only and read-write. Semaphores and lock sets are real kernel objects (`sync_sema.c` 488 lines, `sync_lock.c` 934) exposed through `sync.defs`. There is no `mach_make_memory_entry` and no `vm_remap` RPC (there is a `vm_remap` trap, 86). |
| G11 | OSF `libpthreads` (in OSFMK, ~1,900 lines) is `PURE_MACH = 1` — it needs no libc beyond `printf` and `errno`. It implements IEEE 1003.1c including `pthread_cancel`, `pthread_testcancel`, TSD and `pthread_once`. Mutexes and condition variables each create their own Mach semaphore (`semaphore_create` in `pthread_mutex_init`/`pthread_cond_init`), i.e. one kernel object per lock, versus NetBSD's one per thread. |
| G12 | NetBSD x86 SMP/ACPI code sizes (5.0 → 10): `mpbios.c` 1,222 → 1,437; `mpacpi.c` 1,265 → 1,114; `lapic.c` 627 → 1,018; `ioapic.c` 590 → 622; `cpu.c` 1,089 → 1,489; `intr.c` 1,066 → 2,386. All depend on NetBSD autoconf (`sys/device.h`), UVM, `bus_space` and its interrupt framework, so they are ports, not imports. The register headers `i82489reg.h` (203 lines), `i82093reg.h` (116) and `mpbiosreg.h` (128) have **zero includes** and are directly usable. |
| G13 | **GNU Mach is GPL-2+, so code reuse is out.** Checked headers: `acpi_parse_apic.c` ("Min_SMP is free software … GPL"), `apic.c`, `smp.c`, `ioapic.c` all GPL-2+. Two exceptions carry inherited permissive notices: `i386/i386/mp_desc.c` (CMU 1991) and `i386/i386/apic.h` (University of Utah 1994, from Mach 4) — but those are the *old* inherited files, and 7.3 already has equivalents. Treat the rest as design reference only. As a design reference it solves this exact problem in this exact kernel family: `i386/i386at/acpi_parse_apic.c` 653 lines (RSDP scan, checksum, RSDT/XSDT, MADT walk for LAPIC / IOAPIC / IRQ override, plus the HPET base address), `i386/i386/apic.c` 499, `i386at/ioapic.c` 493, `i386/i386/smp.c` 213 (INIT then STARTUP IPI, with a legacy fallback), `i386/i386/mp_desc.c` 344 — the same file name as 7.3's. ~2,200 lines total, with no autoconf/UVM-style dependencies. Also `kern/gsync.c` 537 (futex equivalent), `device/intr.c` (IRQ delivery to userland), an x86_64 port and a Xen port. |
| G14 | **XNU's i386 platform files are APSL-only** — `acpi.c`, `lapic_native.c`, `mp.c`, `hpet.c`, `cpu_topology.c` all carry `@APPLE_OSREFERENCE_LICENSE_HEADER@` with an Apple copyright and **no** inherited CMU/OSF permission notice, so none is usable as permissive code. As a design reference, XNU has the modernized descendants of 7.3's own i386 files: `osfmk/i386/acpi.c` 757 (RSDP/RSDT/XSDT table lookup, MADT walk, sleep/wake/hibernate), `hpet.c` 471, `lapic_native.c` 1,199 (includes x2APIC), `cpu_topology.c` 388, `mp.c` 2,232 (`intel_startCPU`), `tsc.c` 352, plus the commpage. Two caveats: XNU gets the RSDP from EFI (`efi_get_rsdp_physaddr`), so a multiboot kernel must scan for it; and open-source XNU has **no AML interpreter** — that lives in the closed AppleACPIPlatform.kext. XNU does carry ACPICA's `actbl.h` as `EXTERNAL_HEADERS/acpi/Acpi.h` / `Acpi_v1.h` (462 lines) under **Intel's permissive licence**, so the table and MADT structure definitions are usable directly (better taken from `nmartin0/acpica`). |
| G15 | **Hurd userland** (GPL, architecture reference): the `acpi` translator is 249 lines linking Debian's `libacpica`, so AML runs in user space; `pci-arbiter` serialises PCI config access; `libirqhelp` delivers IRQs to user drivers; `rumpdisk` links rump `ahcisata`, `piixide`, `ata`, and USB mass storage. This is the proof that K8b can live outside the kernel. |
| G17 | **Mach 4 / xMach / OSKit-Mach have no SMP.** In the xMach mirror (`neozeed/xMach`), `kernel/kernel/imps/` is the whole MP story: `apic.h` (Utah 1994, permissive — register and struct definitions only), `cpu_number.h` 50 lines, `cpus.h` 24, and `imps.c` **51 lines of stubs** — `start_other_cpus()` prints "start other CPUs please!!!" and `interrupt_processor()` panics. xMach's author described SMP as "a work in progress" in 2001 and the project ended shortly after. GNU Mach's SMP work (2018–2020) had to recover that same Utah `apic.h` and build everything else new. |
| G18 | **ACPICA is the permissive donor**, SPDX `BSD-3-Clause OR GPL-2.0-only`. Its table manager alone — `source/components/tables/` (`tbxfroot.c` 307, `tbxface.c`, `tbutils.c`, `tbfadt.c`, `tbfind.c`, `tbinstal.c`, `tbdata.c`, `tbprint.c`, `tbxfload.c`; 4,619 lines total) — gives `AcpiFindRootPointer`, `AcpiInitializeTables` and `AcpiGetTable` with no AML interpreter and only a handful of OSL functions to supply. `nmartin0/acpica` is already a fork of it. |
| G16 | Older Mach trees in the reference collection (mach4-UK22, MkLinux, pmk1.1, xMach, macMach) all predate ACPI. **7.3's `mp_v1_1.c` (1,225 lines, INIT + double STARTUP IPI, LAPIC and IOAPIC setup, MP-table discovery) is the most capable i386 SMP code in any permissively licensed Mach**, by a wide margin. |
| G19 | **ACPICA minimal table subset** (`BSD-3-Clause OR GPL-2.0-only` on every file): `components/tables/` — `tbxfroot.c` 307 (`AcpiFindRootPointer`, the RSDP scan), `tbutils.c` 483 (RSDT/XSDT walk, checksums), `tbdata.c` 1,299, `tbinstal.c` 331, `tbfind.c` 147, `tbfadt.c` 758, `tbprint.c` 171, `tbxface.c` 609 (`AcpiInitializeTables`, `AcpiGetTable`); plus `components/utilities/` — `utcksum.c`, `utascii.c`, `utlock.c`, `utmutex.c`, `utownerid.c`, `utglobal.c`. **5,417 lines.** **Exclude `tbxfload.c` (514)** — the only file in `tables/` calling `AcpiNsLoadTable`, `AcpiNsInitializeObjects`, `AcpiEvInstallRegionHandlers`, `AcpiEvUpdateGpes`; excluding it is what keeps AML out. OSL functions required, exactly seven: `AcpiOsGetRootPointer`, `AcpiOsMapMemory`, `AcpiOsUnmapMemory`, `AcpiOsAcquireLock`, `AcpiOsReleaseLock`, `AcpiOsTableOverride`, `AcpiOsPhysicalTableOverride` (the last two may return "no override"). Headers: `source/include/` is 27,793 lines total; `actbl.h` + `actbl1–3.h` + `actypes.h` alone are 9,825, and a platform header (model on `acfreebsd.h` / `acnetbsd.h`) is needed. |
| G20 | **`nmartin0/acpica` is upstream ACPICA**, not illumos code: 1,958 files, upstream `source/generate/tests/documents` layout, last commit "iasl: multiply-defined symbols", 15 March 2021. Usable, but a 2021 snapshot — prefer current upstream. XNU took the headers-only route from the same source: `EXTERNAL_HEADERS/acpi/Acpi.h` / `Acpi_v1.h` (462 lines) is an older `actbl.h`, and `osfmk/i386/acpi.c` hand-writes the walk. |
| G21 | **BSD donor files, licence as written in each file.** Dependency-free headers, usable as-is: NetBSD `sys/arch/x86/include/i82489reg.h` 203 (LAPIC incl. x2APIC MSRs), `i82093reg.h` 116 (IOAPIC), `mpbiosreg.h` 128 (MP spec tables), `sys/dev/ic/hpetreg.h` 71, `hpetvar.h` 54 — all TNF two-clause. Drivers (permissive but tied to autoconf/UVM/`bus_space`/intr frameworks, so ports not imports): NetBSD `lapic.c` 1,018, `ioapic.c` 622, `mpbios.c` 1,437, `cpu.c` 1,489, `sys/dev/ic/hpet.c` 283 (Nicolas Joly, 2-clause, smallest HPET driver of the three). FreeBSD: `sys/x86/acpica/madt.c` **778, BSD-2-Clause** (cleanest MADT consumer anywhere), `sys/x86/include/apicreg.h` 551 BSD-2, `io_apic.c` 1,269 BSD-2, `mptable.c` 1,296 BSD-2, `local_apic.c` 2,462 BSD-3, `mp_x86.c` 1,786 (3-clause, no SPDX), `acpi_hpet.c` 1,007 (2-clause, no SPDX). OpenBSD: `sys/dev/acpi/acpimadt.c` **476, ISC** (smallest MADT walker), `lapic.c` 746, `i82489reg.h` 149. ⚠ **NetBSD `sys/arch/x86/x86/mpacpi.c` 1,114 is four-clause BSD** (Wasabi Systems / Frank van der Linden, advertising clause) — avoid; FreeBSD's `madt.c` is the BSD-2 equivalent. |
| G22 | **7.3's `i386/apic.h` (124 lines, OSF permissive) already defines both APICs**: `LAPIC_ID`, `VERSION`, `TPR`, `APR`, `PPR`, `EOI`, `REMOTE_READ`, `LDR`, `DFR`, `SVR`, ISR/TMR/IRR bases, `ERROR_STATUS`, `ICR`, `ICRD`, `LVT_TIMER`, `LVT_LINT0/1`, `LVT_ERROR`, the timer count and divide registers, plus `IOAPIC_START`, `IOAPIC_RSELECT`, `IOAPIC_RWINDOW`, `IOA_R_ID`, `IOA_R_VERSION`, `IOA_R_REDIRECTION`. What is missing is x2APIC MSRs and newer IOAPIC entry bits. |
| G23 | Permissive Mach-family files that exist but add nothing: `neozeed/xMach` `kernel/kernel/imps/apic.h` (Utah 1994, struct/register definitions only), `cpu_number.h` 50, `cpus.h` 24, `imps.c` 51 (stubs); GNU Mach's `i386/i386/apic.h` is the same Utah file, and its `mp_desc.c` 344 carries the CMU 1991 notice but is the inherited file 7.3 already has at 343 lines. |
| G24 | Full inventory with paths, line counts and dependency notes: companion document *Permissive source inventory: ACPI, APIC, SMP and HPET for OSFMK 7.3*. Shortlist recorded as K8c, K8d, K9a, K14a. |
| G25 | **Full licence census of xnu-123.5 (Darwin 0.3, 1999; 2,759 files, every file checked).** In `osfmk/`, `iokit/`, `libkern/`, `libsa/`, `pexpert/` there is **no permissively licensed source file without an APSL header** — every non-APSL file there is build plumbing (Makefiles, `conf/MASTER*`, `conf/files*`, `doconf.csh`, `newvers.csh`, version files, four `conf/copyright*` templates). Dual-noticed counts: `osfmk` 588 files carry APSL **over** CMU/OSF, `bsd` 514 over Berkeley and 226 over NeXT, `iokit` 511 APSL-alone. 593 `osfmk` files carry OSF's notice only as the unexpanded token `@OSF_COPYRIGHT@` / `@OSF_FREE_COPYRIGHT@`, with the text in `conf/copyright.osf`; 7.3 has them expanded in place. Apple's header asserts APSL over the file as shipped, so the usable part of a dual-noticed file is only the original text — which 7.3 already contains. |
| G26 | **xnu-123.5 has nothing modern to want**: its `osfmk/i386` is 7.3's i386 tree plus Apple's changes (`apic.h`, `AT386/mp/`, `mp_desc.c`, `user_ldt.c`, `pcb.c`, `fpu.c`). No ACPI, no MADT, no HPET, no x2APIC, no commpage — all of which arrived in XNU between 2005 and 2008 under APSL. |

| G30 | **GNU Mach licence sweep (full history, 3,107 commits from the 1997 Mach 4 import to July 2026; 1,170 files).** Distribution: 265 files with an explicit GPL notice, 383 carrying only a CMU and/or Utah permissive notice, 356 with no notice, plus Linux-derived driver glue (91 + 47 GPL). **None of the permissive-noticed files is a clean permissive addition.** Two reasons: (a) 339 of the 383 have been edited in the FSF era (more than one commit), with no added grant, inside a GPL-2 project — `COPYING` is GPL-2; (b) the ones that are genuinely new are Mach 4 / Utah artifacts — MIG `.srv`/`.cli` stubs, `ipc_target.c`, `refcount.h`, `shuttle.h`, small headers, build glue. Only 9 permissive-noticed files were first added after 2000, and they are `x86_64/cswitch.S` (2012), the recovered Utah `i386/i386/apic.h` (2020), test headers and docs. Every modern subsystem carries an explicit GPL notice: `kern/slab.c`, `kern/gsync.c`, `kern/smp.c`, `i386/i386/smp.c`, `i386/i386/apic.c`, `i386/i386at/ioapic.c`, `i386/i386at/acpi_parse_apic.c`, `vm/vm_page.c`, `i386/i386/cpuboot.S`. |
| G31 | **The x86_64 port is the interesting near-miss.** Its assembly carries only the CMU 1991 notice — `cswitch.S` 148 lines, `locore.S` 1,682, `idt_inittab.S` 145, `kdasm.S` 133, `_setjmp.S` 65, `syscall_sw.h` — but the files were created in 2012 by Samuel Thibault (and edited since by Damien Zammit) as adaptations of the CMU i386 originals, with no new copyright line and no new grant. Retaining a notice is not a grant for the new work, so treat as GPL. **Practical consequence:** these are adaptations of files 7.3 already contains (`i386/locore.S` 1,529 lines vs 1,682; `cswitch` 139 vs 148) — when K13 needs them, adapt your own copies rather than touching GNU Mach's. |
| G32 | **xMach licence census** (kernel 1,728 files, LITES 944). Kernel: 580 CMU, 318 Utah, 64 CMU+Utah, 16 CMU+Berkeley, 9 CMU+OSF — all with explicit permission grants — against **65 GPL files plus 13 GPL+Linux** (the `i386at/gpl/` Linux driver glue, cleanly quarantined in its own directory). | G33 | **xMach's LITES vs `lites-1.1.u3`: 308 files differ, 6 added, and most differences are Mach 4 API adaptation or CVS keyword noise.** The genuine improvements, all permissive: (1) `liblites/exec_file.c` — program-header-walking ELF classification with `PT_INTERP` detection (U3); (2) `server/miscfs/devfs/` — a working devfs, 1,158 lines, wired into `vfs_conf.c` and `init_main.c` (L26); (3) `emulator/emul_exec.c` — ELF interpreter loading with load bias for dynamically linked binaries (U7); (4) heavily updated Linux personality (`e_linux.c` 424 changed lines, `e_linux_trampoline.c` 431, `e_linux_sysent.c` 114, new `e_linux_getcwd.c`) — not needed for a NetBSD target; (5) small fixes such as the `#ifdef DISKSLICE` → `#if DISKSLICE` correction in `device_misc.c`. | G34 | **The xMach kernel is behind 7.3 except in one place.** It is Mach 4 UK22 (ChangeLog ends April 1996) with light cleanup to 2001: no SMP (G17), fewer drivers than 7.3 (no SCSI, no VGA/ET4000/S3, no EISA, no BIOS label code), and its own MIG/`libmach`/`libthreads` on a `configure`-based build. Same device framework as 7.3. |
| G35 | **OpenMach combed in full** (`github.com/openmach/openmach`, 1,455 files; the sibling repo `openmach/mach4` is the same tree, 51 entries apart). | G36 | **What Mach 4 has that 7.3 does not** (all permissive unless noted): `libmach/exec/` — a **format-agnostic ELF/a.out loader** (`elf.c` 88, `load.c` 39, `exec.h` 130, `elf.h` 298) shared by the kernel's `bootstrap.c`, the bootstrap task's `load.c` and the boot loaders; `i386/kernel/pc/{i16,rv86}` — 1,241 lines of 16-bit and v86 real-mode support for calling the BIOS from protected mode (of interest only if VBE or another BIOS service is ever needed; multiboot2 is the better route); `nhd.c`/`nfd.c` (already recorded as K18); an autoconf-based build with machine-independent and machine-dependent packages split, as an alternative to ODE; and FIPC, Utah's fast IPC, which is the cousin of 7.3's FLIPC and is slated for removal anyway (K12). R27 stands, but as documentation rather than as a blocker. |

| G68 | **POE, assessed.** CMU: *"a very simple server whose main function is to run as the first server on the micro-kernel and to bootstrap other servers"*; Mach-US used it only to exec the other servers. A 2026 GXemul run booted **POE 10.1.0 on MK83** (DECstation 5000/200, Ultrix 4.5 userland) to a shell in ~40 seconds — `echo`, `pwd`, `ls`, `cat`, `date` work, not everything in `/bin` runs, and **writes never reach the device because `sync` is defined as a no-op**. Mary R. Thompson's *A Brief Description of the POE Server* documents *"how system calls are passed from a server via an emulation library to the kernel and back again… the same for the CMU Unix server and at least the early versions of the LITES server."* **Verdict:** bootstrap server and the most compact reference for the emulation-library mechanism; not a path to a POSIX personality — extending it means either writing a BSD kernel or importing one, i.e. rebuilding LITES from an older, 4.3BSD-flavoured, pre-OSF-MK starting point. |
| G69 | **UX 28 source is already in `nmartin0/mach_stuff`** — `macMach5-92src (2)/src/mach_servers/ux.28`, 4.2 MB, beside `mach_init`. `server/` has 372 source files (`bsd`, `sys`, `vm`, `net`, `netinet`, `netimp`, `netns`, `compat`, `vice`, `uxkern`, `mac2`, `mac2_mach`) plus a 15-file `emulator/`. Licence profile: 168 Berkeley+CMU, 158 CMU, 17 Berkeley, 14 none, 9 that merely mention AT&T in comments; **no proprietary or restricted-rights notices**. **Will not boot on 7.3**: machine-dependent code is `mac2`/`mac2_mach` (Macintosh II, m68k) with **no i386 anywhere**; and `uxkern` and `emulator` contain **zero** references to `msgh_seqno`, `security_token` or `NDR_record`, so it predates trailers, untyped messages and the OSF device interface. Porting it would mean redoing Helander's work with older, less POSIX code. |
| G70 | **LITES's Mach glue is UX's, modernised — diffed and confirmed.** 29 of UX's 37 `uxkern` files appear in LITES's `server/serv` under the same names. Proof it is the same code: `inittodr.c`'s entire substantive diff is K&R→ANSI prototypes, two added includes, and a **bug fix** — `wday_name[DAYS_PER_WEEK][3]` → `[4]` (and `mon_name` likewise), the three-character names having had no room for the NUL. What Helander changed: (1) K&R→ANSI throughout, which inflates raw diff counts (`bsd_server_side.c` 2,182 changed lines across files of 1,404 vs 1,400); (2) **OSF-MK portability** — UX has **zero** `OSFMACH3` conditionals, LITES has them in `block_io.c`, `cons.c`, `device_misc.c`, `device_reply_hdlr.c`, `disk_io.c`, `ether_io.c`, `misc.c`, `port_object.c`; (3) `port_hash.c/h` → `port_object.c/h`, a generic port hash becoming a **typed object model** (`POT_PROCESS`, `POT_FILE_HANDLE`, `POT_VNODE_PAGER`, `POT_TASK`, `POT_THREAD`, each with rights and GC discipline) — the machinery X14 plugs into; (4) the RPC interface grew **11 → 29 routines**, adding `bsd_vfork`, `bsd_after_exec`, `bsd_exec_done`, `bsd_vm_map`, `bsd_lseek`, `bsd_getattr`/`setattr`, `bsd_path_getattr`/`setattr`, `bsd_sendmsg_short`/`_long`, `bsd_recvmsg_short`/`_long`, `bsd_sysctl`, `bsd_signal_port_register`, `bsd_zone_info`, `bsd_mon_dump`/`mon_switch`, dropping `bsd_readwrite`; (5) **40 new files with no UX counterpart** — `sendsig.c`, `signal.defs`, `signal_user.c`, `select.c`, `serv_fork.c`, `server_exec.c`, `server_init.c`, `synch_prim.c`, `serv_synch.c`, `vm_glue.c`, `vm_syscalls.c`, `vn_pager_misc.c`, `xmm_interface.c`, `mapped_timezone.c`, `mach_init_ports.c`, `notify_interface.c`, `timer.c`, `tape_io.c`, `proc_stats.c`, `cprocs.c`. **Practical map: editing `device_misc.c` or `ux_exception.c` means editing 1992 CMU code; editing `sendsig.c` or `select.c` means editing Helander's, which is where the decisions the L-series questions were actually made.** |
| G71 | **pmk1.1 versus the MkLinux 7.3 import.** Same version stamps (`PMK`, 3/0/1/.1) and the same byte-identical `copyright.osf`. Of 1,307 shared `mach_kernel` files: **7 identical, 1,212 differing only in the copyright line and a `pmk1.1` → `MkLinux` tag, 88 with real changes.** MkLinux adds **221 files** (70 `chips` — the directory goes from 1 file to 67 — 38 Sequent, 35 `uk_xkern`, 30 PowerPC, 19 i386) plus the whole `xkern` tree; pmk1.1 has 22 files 7.3 lacks, almost all pre-`.S` assembly (`bcopy.s`, `cswitch.s`, `kdasm.s`, `slave_boot.s`, `_setjmp.s`). Substantive changes cluster in PowerMac (`ppc/net_filter.c` 706 lines, `POWERMAC/pci.c` 252, `mesh.c` 245, `pmu.c`, `hw_exception.s`, `pmap.c`) and in `i386/AT386/model_dep.c` (206) and `hd.c` (112). **Biggest single change: `kern/bootstrap.c` 917 → 1,671 lines**, adding `mach/elf.h`, `i386/multiboot.h`, `boot_script.h` and an ELF program-header loader; `kern/boot_script.c` ("Boot script parser for Mach. Written by Shantanu Goel") **does not exist in pmk1.1** — so the Hurd-style bootstrap graft is a MkLinux-era addition, not OSF's (Q7). Its userland is *thinner* than 7.3's: `cmds` holds only `mach_perf`, and its three servers are the same stubs. **Use: diff reference, not a source of code.** |
| G72 | **CMU release numbering is denser than any catalogue shows.** MK42's own `MERGE_HISTORY` documents twelve consecutive releases — MK31 through MK42 — one section each. OSF's trees reference **MK68** (4 files) and **MK71** (30 files in 6.1, 26 in 7.3) as merge points, and nothing later, placing the OSF fork around late 1992. Public catalogues list only mk42, mk78, mk80, mk82, mk83, mk83a, mk84 — so MK58 and others exist without being listed. `liexusong/mach` is a CMU tree at `VERSION = MK83` whose merge notes cover **MK83A/MK84**: MIG gains power-of-2 field alignment for the Alpha; scripts to flatten the tree and build with NetBSD makefiles; a NetBSD boot program; **"a few changes from Johannes Helander to support LITES"** — dating LITES support entering CMU Mach; AHA17 SCSI on i386AT; the `device_write` fix in `vm_copyin_to_page_list`; and an **incompatible Alpha change** making `catch_exception_raise` 64-bit clean, such that "MK84 will NOT work with the current UX server (UX42 and below)". Platform support narrows to i386 (ISA/PS2), DECstation MIPS and Alpha; Sequent tested but "our Sequent has broken"; Luna88k compiled, not run. |
